# 陳柏丞：看護角色七天功能測試計畫

規劃日期：2026-10-25。測試者：陳柏丞；主要角色：長輩 1 的看護。

圖片原排程為 10/22–10/28。以下使用 D1–D7，不將未操作的日期回填為完成；若 10/25 開始，對應 10/25–10/31。

本文件是操作規劃，沒有建立帳號、填入正式資料或執行測試。角色範圍依目前本機頁面與 Rules 核對，不代表正式後端每項權限已重新驗證。

## 1. 先確認看護到底能做什麼

操作均以「已加入、仍有權存取的長輩」為前提。

| 功能 | 看護可執行的操作 | 不要誤排的操作／驗證界線 |
| --- | --- | --- |
| 帳號 | 註冊看護、登入、登出；修改本人姓名、頭像、聯絡電話 | 不替家屬修改帳號；重複註冊用另備的帳號，不每天重建主帳號 |
| 長輩關聯 | 輸入邀請碼申請加入、查看申請狀態、選擇已連結長輩、解除本人關聯 | 核准申請、撤銷及產生新邀請由有權家屬處理；解除前先備妥重新加入流程 |
| 藥單 | 拍照／選圖、OCR、結果校對與建立；查看藥單與藥品彙整；修改及刪除可存取的藥單 | 目前版本允許所屬看護編修及刪除，不能沿用「只有主要家屬可改」的舊說明；刪除只使用另外建立的可刪副本 |
| 相機 QR 掃描 | 掃描 http/https 網址並開啟連結；拒絕非網址 QR | 這個按鈕不是直接匯入藥單，也不是長輩邀請碼輸入框 |
| 用藥確認 | 在有效時間內按 DONE／完成，查看當日進度及其他成員同步 | 同時段防重複；目前確認紀錄沒有修改／刪除流程 |
| 健康 | 新增體溫、心跳、血壓、血糖；選空腹／餐後；查看四類趨勢與期間 | 看護健康頁目前提供新增與趨勢，沒有健康紀錄編輯／刪除按鈕；不要把 Rules 允許視為有 UI 可操作 |
| 行事曆 | 新增、修改、完成及刪除行程；切換日期／月份 | 其他長輩資料不可混入 |
| 每日事項 | 新增、修改、勾選、取消勾選及刪除事項 | 和行事曆行程分開驗證，不能只測其中一個 |
| 記事本 | 新增、修改、置頂／取消置頂、刪除可操作的記事 | 每天保留一篇交班記事，刪除用另外的短記事 |
| 身體狀況影像 | 拍攝／選取照片及影片，新增單筆或資料夾、加入子項目、修改文字、刪除可操作的內容；查看及播放 | 影片拍攝上限目前為 60 秒；規劃先用 5–10 秒；日常功能檢查不刪除既有正式紀錄 |
| 溝通語音圖卡 | 播放家屬上傳的八類語音，停止、切換；未錄音時查看提示 | 看護這個頁面沒有錄音按鈕，錄音準備請家屬完成 |
| 聊天 | 在長輩的照護群組傳文字／照片、查看對方回覆與發送者資訊 | 家屬專用聊天室不是看護的聊天範圍；目前訊息沒有編輯／刪除流程 |
| 通知 | 查看、分類／長輩篩選、開啟詳情及已讀狀態 | App 內通知與 iPhone 背景推播分開記錄；通知列表出現不代表推播已送達 |
| 看護手冊 | 閱讀家屬維護的內容、核對版本、確認已交接 | 看護不可在此修改手冊內容；家屬改版後，重新確認新版 |
| 緊急聯絡 | 開啟已設定聯絡電話的選擇與系統撥號 | 用參與測試且同意接聽的家屬電話；也可停在系統確認畫面後取消 |
| 仲介綁定 | 輸入仲介邀請碼、查看綁定狀態 | 目前更換／解除仲介需要管理者協助，不能排成看護自行解除 |
| 語言／介面 | 中文、英文、越文、印尼文切換，檢查同頁排版及內容 | 動態翻譯可能依賴 OCR 同一後端，失敗需單獨記錄 |
| 本人資料 | 隱私政策、我的資料、個資修正；重新驗證後匯出 JSON／手機分享 | 匯出以本人建立且仍可存取的資料為準，不要求等同整個群組的所有紀錄 |
| 刪帳 | 查看流程、重新驗證、申請、取消申請 | 真正申請用備用看護帳號；30 天到期清除在隔離環境驗證，不以七天實測宣稱通過 |
| 非看護功能 | — | 仲介名單／趨勢／通報處理、家屬社群發文、主要家屬轉移、全站 Audit Log 管理，不列入陳柏丞個人必測 |

核對依據：`app/caregiver/`、`src/care-target/permissions.ts`、`firestore.rules`、`app/account-settings.tsx`、`app/care-target/`。

## 2. 開始前準備

1. 確認陳柏丞的 App 帳號角色為看護，且已連結長輩 1；請家屬確認畫面上的長輩姓名。
2. 家屬兩人各準備一部裝置或獨立登入工作階段；仲介陳詩穎準備綁定碼，協助確認看護資料有同步。
3. 再準備一個可重建的備用看護帳號及一位輔助長輩。註冊、退出、重新加入、刪帳申請用這組做；不要讓主要七天帳號中途失去資料。
4. 若要測跨組權限，由長輩 2 的參與者配合提供測試用連結；沒有授權加入前，預期看不到其資料。測切換長輩則使用已正式邀請加入的輔助長輩。
5. 準備去識別化藥單：清晰單藥、多藥、傾斜／模糊各一張；另備無文字圖片及可刪藥單副本。藥名、劑量、頻率的預期值以樣張逐字核對，不以 AI 回傳作為答案。
6. 家屬建立手冊並錄好八張圖卡：用藥、吃飯、洗澡、如廁、運動、喝水、睡覺、情緒。另保留一張未錄音的狀態供測試。
7. 準備照片兩張、5–10 秒短片兩支、約 150–250 字長訊息一段；內容不含真實健康或身分識別資料。
8. 確認手機相機、相簿、麥克風及通知權限；測拒絕權限後再恢復。iPhone Expo Go 的限制要記為環境限制，必要時另用 development build 驗收。
9. 每天記下 App 提交版本、手機型號、iOS／Expo Go 版本、實際日期與 Wi-Fi。開發 QR 必須用當下 Wi-Fi 位址；Expo Go 依平台要求登入對應 Expo 帳號。

合成健康數據僅用於協調好的展示／驗收群組，不當成真實量測或醫療處置依據；若主要群組已有真實照護資料，另建專用驗收長輩。

已知前置問題：前次檢查 OCR `123.195.84.227:8000` 連線逾時，開始當天須重新確認。若仍失敗，拍照／選圖可以分段驗證，但 OCR、結果建立及依賴它的動態翻譯不能填「通過」。

## 3. 每天都要跑的核心流程

每天約 60–90 分鐘，另加當日專項約 20 分鐘。測試時間可配合作息平移，用藥時間以樣本藥單實際設定為準。

| 編號 | 每日操作 | 通過條件 |
| --- | --- | --- |
| C01 | 登入，確認看護身分、長輩姓名、首頁；收尾登出再登入一次 | 登入正確角色，重新登入後沒有切到別人的長輩 |
| C02 | 藥單入口拍照／相簿選取；嘗試 OCR；查看列表、詳細、藥品彙整 | 圖片可選；OCR 對照樣張；已儲存結果重開一致。失敗階段分別標記 |
| C03 | 在當日可刪副本修改備註並重開；測刪除確認／取消 | 修改持久保存；取消不刪除。實際刪除放當日專項，用新副本 |
| C04 | 在有效時間完成用藥確認，查看進度；再按一次 | 正確時段、日期、長輩；同時段只算一次，家屬看得到。不要假設一種藥等於一筆 DONE |
| C05 | 早／晚各新增一筆健康資料；查看四類圖表 | 每筆值、單位、血糖類型、時間正確；重新開啟可查到 |
| C06 | 看今日行事曆；新增一個小行程，修改，勾完成 | 家屬可見；標題、日期與完成狀態一致；多餘暫存行程可刪 |
| C07 | 每日事項新增一項，修改，勾選／取消；刪一個另建項目 | 狀態與清單數量一致，不影響昨天事項 |
| C08 | 建一篇當日記事，修改、置頂再取消 | 重新開啟仍保留正確內容；另建的短記事可刪 |
| C09 | 新增當日影像紀錄或子項目；查看照片／影片 | 文字、媒體與長輩正確，家屬可見；至少播放一支已上傳短片 |
| C10 | 開語音圖卡，播放一張、停止、切換到另一張 | 不同語音不重疊；沒錄音的圖卡有提示、不崩潰 |
| C11 | 在照護聊天室傳 2–3 則文字及 1 張照片，家屬回覆 | 雙方收到，姓名、順序、圖片正確；重開不重複發送 |
| C12 | 查看通知分類、詳情與已讀；觀察一次背景推播 | App 內與背景分列結果；沒有預期通知時先確認觸發條件，不能直接算零筆正常 |
| C13 | 開手冊、核對版本與交接狀態 | 已確認的版本不每天重複產生確認；家屬發布新版時才重新確認 |
| C14 | 語言切換；首頁／表單／聊天各看一次；返回中文 | 長字不相撞、按鈕可點、鍵盤不蓋儲存鍵、沒有原始程式錯誤 |
| C15 | 開帳號設定、我的資料、隱私政策、綁定仲介、切換長輩清單 | 本人資料與關聯正確；當天沒有新修訂就檢查讀取，不反覆改名或重綁 |
| C16 | 重新驗證並匯出有資料 JSON，打開手機分享面板後取消 | 檔案可解析、含本人當日可匯出紀錄，不混入他組資料；取消分享可正常返回 |
| C17 | 進解除關聯／刪帳頁檢查說明後返回；開緊急聯絡並取消 | 返回後仍可使用，沒有意外解除、送出刪帳或撥號 |

「每天所有功能測一次」採每天遍歷所有功能區、執行正常核心流程；首次註冊、實際退出、刪帳等會改變帳號狀態的完整操作分配到專項，不能拿每日查看頁面冒充已測過完整流程。

用藥特別注意：目前前端有效操作窗為排程時間前 30 分鐘至後 60 分鐘。例：08:00 的樣本排程，07:30–09:00 操作；跨日、離窗及邊界另列專項。不修改手機時鐘，也不為了通過測試把真實藥單改時間。

## 4. 七天情境：每天先跑 C01–C17，再做當日加強

| 天數 | 情境 | 當日專項 | 可直接使用的自然訊息／記事 |
| --- | --- | --- | --- |
| D1 | 第一次接手照護 | 備用帳號測註冊：未同意政策、弱密碼、重複 Email；有效邀請加入及等核准狀態；主帳號完成仲介綁定、手冊交接；清晰樣張 OCR；權限先允許 | 「今天開始由我協助照護，已閱讀照護手冊。接下來會在這裡回報日常狀況與照護紀錄。」 |
| D2 | 規律生活與容易重複操作 | 連點儲存／DONE／發送；同時段多種藥；行事曆／事項／記事完整新增改刪；模糊照片重拍；尚未錄音圖卡；準備一組未使用的邀請碼留到 D3 過期再測 | 「今天依原定安排完成紀錄，下午散步的行程已放進行事曆，若時間需要調整再告訴我。」 |
| D3 | 數值變動與提醒 | 先核對家屬設定的門檻，輸入合成超門檻值；確認通知收件人、內容、數值及點擊導向；測空白表單、體溫 99 等超出表單範圍值；未用邀請碼滿 24 小時後拒絕；不要改時鐘 | 「這次紀錄與前兩天有些差異，數值已更新，請查看健康紀錄。我會把後續觀察持續記在這裡。」 |
| D4 | 回診與新版交接 | 行事曆約定回診 → 相簿多藥樣張 OCR → 核對並存新藥單 → 原樣本停用／更新由有權操作者處理 → 家屬改手冊 → 看護重新確認 → 聊天回覆；未讀／已讀同步 | 「回診資料已整理，新的藥單與備註請一起確認。照護手冊若有更新，我會重新閱讀並完成交接確認。」 |
| D5 | 照片、影片與多語溝通 | 單筆照片、文字紀錄、資料夾加照片及 5–10 秒影片；修改文字、刪除暫存子項；相機／相簿拒絕後恢復；八張圖卡全部播放，換背景再返回；四語言長字排版 | 「下午活動的照片與短片已放在狀況紀錄，方便你們一起查看。晚間注意事項也補進記事本了。」 |
| D6 | 斷線、重試與跨組隔離 | 單一表單逐項斷網後儲存／恢復，不同功能分開測；重新登入與重開；備用帳號在已授權的輔助長輩切換；未連結長輩應拒絕存取；仲介核對服務摘要／通報狀態，操作由仲介負責 | 「剛才網路短暫中斷，恢復後已重新確認紀錄是否送出，避免重複登記。」 |
| D7 | 一週交班與資料收尾 | 核對七天圖表、用藥進度、照片、記事與聊天；本人 JSON 匯出及實際存到指定私人位置；備用帳號退出→失去存取→重新邀請；備用帳號刪帳申請→取消→恢復登入；回歸前六天失敗項 | 「這一週的紀錄已整理完成，回診、每日事項及交班備註都可以在 App 查閱，接班時再一起核對。」 |

回診情境只做資料流程演練，不據此變更真實用藥。若 UI 沒有「停用」控制，就記錄現有編修／刪除行為並請負責者選擇處理方式，不把不存在的按鈕列為完成。

## 6. 自然內容與媒體安排

- 每日事項：「早餐後整理餐桌」「上午陪同散步」「下午確認回診資料」「晚間整理明日用品」。當日勾選結果要與記事一致。
- 行事曆：D2 建立 D4 09:30「門診回診」；D3 修改為 10:00，聊天同步告知；D4 完成，檢查家屬端時間一致。
- 記事標題：D1「照護習慣交接」、D2「今日活動安排」、D3「持續觀察紀錄」、D4「回診後交接」、D5「下午活動紀錄」、D6「網路恢復後核對」、D7「本週照護整理」。
- 照片：餐點擺放、收妥的隨身物品、空的活動區域；影片：5–10 秒的活動空間或物品。避免拍到非參與者及識別資料。
- 家屬語音例句：「準備吃飯了，我們慢慢來。」「水杯放在旁邊，想喝水可以告訴我們。」「今天辛苦了，先休息一下。」看護端測播放；家屬端負責錄音及更新。
- D4 交接記事需記下「藥單名稱／版本、回診時間、下一次行程、待家屬確認事項」；聊天室及手冊內容需能互相對上。

## 7. 特殊情境與預期結果

| 情境 | 預期與紀錄方式 |
| --- | --- |
| OCR 主機不可用 | 有清楚失敗提示，可返回或重試；OCR 辨識／結果儲存記 B 或 F，不以能選圖代替成功 |
| 未到用藥時間 | 不建立成功確認；記實際排程及點擊時間。超時與漏服提醒依後端觸發條件另驗證 |
| 用藥按鈕連點 | 同長輩、同日期、同排程時段只算一次；不是每點一次都多一筆 |
| 健康儲存斷線後重試 | 失敗／等待狀態清楚，恢復後核對資料筆數，不因重試多存；不得只看成功彈窗 |
| 聊天斷線 | 分辨待送、失敗與送達；重開對方帳號確認數量，不能靠手機本地看到氣泡判定 |
| 看護手冊改版 | 舊版已確認不等於新版已確認；家屬更新後看到新內容並重新確認 |
| 切換長輩 | 藥單、健康、聊天、影像、記事與手冊全部切換；舊畫面回呼不能把資料放到新長輩 |
| 解除關聯 | 只移除本人關聯；看護失去存取，家屬仍保有原照護內容；只用備用帳號實作 |
| 匯出 | 確認 JSON 可讀且符合本人資料範圍；對方發出的訊息及其他人成員資料不要求完整包含 |
| 手機拒絕相簿／相機權限 | 有提示且可退出，恢復權限後可再操作，沒有無止境轉圈 |
| 推播 | 分別記 App 內通知、手機背景通知、點擊導向；若 Expo Go 不支援則記 B，改 development build 補驗 |
| 帳號刪除 | 備用帳號申請與取消可實測；30 天到期及保存期限實刪在隔離環境另驗，不改正式伺服器日期 |

## 8. 每日紀錄與影片

每個案例一列，欄位如下；記錄請勿放密碼、Token 或未遮蔽的藥單。

| 日期／時間 | 案例編號 | 長輩／角色 | 操作與輸入 | 預期結果 | 實際結果 | P/F/B/N | 截圖或影片時間碼 | 問題編號／重測 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 實際填寫 | C05 | 長輩1／陳柏丞看護 | D1早健康資料 | 正確儲存一筆、家屬可見 | 待執行 | N | 待補 | — |

P＝實際操作通過；F＝已操作但結果不符；B＝被網路、後端、權限、裝置支援或協作者阻擋；N＝尚未操作。取消對話框只能證明取消分支，不代表實際刪除通過。

每天建議錄兩段：

1. 正常流程 8–12 分鐘：登入與長輩 → 藥單 → 用藥 → 健康圖表 → 行程／事項／記事 → 影像／語音 → 聊天／通知 → 交接與匯出。
2. 當日專項 3–6 分鐘：保留失敗、重試與對方同步結果；錄到問題先記時間碼，不剪成只有成功畫面。輸入密碼時暫停錄影。

影片片名例：`D1_陳柏丞_正常流程.mp4`、`D3_數值變動與通知.mp4`。每段開頭口述實際日期、角色、長輩與情境，不說成已完成整體驗收。

## 9. 七天結束的核對數量

- 7 天核心案例皆有 P/F/B/N，沒有留白；所有 F／B 都有原因、影響及重測結果。
- 基礎健康資料 14 筆，含四類數值；若為門檻另外加資料，要分開列數量。四類圖表都核對 1 周／2 周／1 個月／全部，不能宣稱已有一個月資料。
- 用藥確認數＝每日實際安排且已完成的排程時段合計；若樣本設定每天 3 個不同時段且七天全部完成，才預期 21 筆／時段。離窗拒絕與連點不增加筆數。
- 至少保留每日記事各一篇、每日聊天照片各一張、每日雙方文字對話；訊息列數與雙方實際送出次數對照。
- 照片、影片、單筆紀錄、資料夾與子項目都有建立、重開、編修及可刪副本刪除的證據；八種圖卡都播放過。
- OCR 清晰／多藥／模糊重拍／非藥單各有結果；若主機未恢復，這一組保持 B，不得寫成整體通過。
- 至少一份七天收尾匯出可在私人位置打開，且已和本人可匯出紀錄比對。
- 備用帳號完整加入、退出、重加、刪帳申請與取消有證據；主帳號與既有照護資料保持可用。
- 最終結論使用「看護角色已完成哪些實機案例、仍缺哪些」，不把家屬、仲介、管理員或 30 天排程算成陳柏丞已驗收。
