# 註冊重試修正（2026-10-24）

## 變更

- 註冊不再以手機快取中的登入身分直接重新驗證；先以本次輸入建立帳號。
- 若 Auth 帳號已存在，重新驗證本次帳密後，只接續沒有個人檔案的註冊。既有、重複或無效檔案仍拒絕建立，沒有覆寫角色或隱私同意。
- 表單驗證與送出使用相同的 Email 正規化方式。
- 憑證與連線錯誤使用既有多語提示；不再記錄原始註冊錯誤訊息。
- 沒有修改 Firebase Rules、Cloud Functions 或密碼政策。

## 驗證

- 註冊、密碼、四語錯誤提示：26 項測試通過。
- TypeScript `tsc --noEmit` 與變更檔案 ESLint：通過。
- 正式 Firebase、獨立桌面瀏覽器：新看護帳號註冊成功。
- 合成帳號只有 Auth、未建立個人檔案，關閉工作階段後從註冊頁接續：成功進入看護路由。
- 既有看護以相同帳密選擇仲介再次註冊：顯示已註冊提示；重新登入仍為看護，角色未覆寫。
- 使用者指定帳號：由 App 註冊頁建立成功，新瀏覽器工作階段登入成功。帳密未寫入測試檔或報告。
- Expo iOS manifest 與最新 bundle 均回應 HTTP 200。

## 限制

- 原 iPhone 的失敗原因沒有取得可對應到該次操作的錯誤紀錄，不能宣稱已重現原始原因。
- 本次實測為桌面瀏覽器連接正式 Firebase，不等同 iPhone 實機驗收。
- 合成驗證帳號沒有加入任何照護群組，也未刪除或改動既有照護資料。
- 這是前端修正，Expo Go 需重新載入目前 Metro 版本；不是新安裝包發行。
