# 家庭照護群組

## 功能規則

- 一位長輩固定對應一個家庭照護群組，群組 ID 與 `patientId` 綁定。
- 使用者不能自行建立、命名或複製其他家庭群組。
- 家屬或看護仍須透過既有邀請碼與核准流程加入長輩的照護關係。
- 核准後，Firestore 會依 `patients.families` 與 `patients.caregivers` 自動授予家庭群組權限，不維護第二份群組成員名單。
- 解除照護關係後，使用者也會同步失去群組讀寫權限。

## 聊天空間

| 畫面 | Firestore 路徑 | 用途 |
| --- | --- | --- |
| 看護／家屬對話 | `chats/{patientId}/messages` | 保留原本的一對照護溝通入口 |
| 家庭群組 | `chats/{patientId}/familyMessages` | 同一位長輩的家屬與看護共同交流 |

圖片沿用既有的 `chats/{patientId}/images` 儲存路徑，以相容目前部署的
Firebase Storage 權限設定；訊息文件仍分開存放，不會混入另一個聊天室。

## 權限與資料生命週期

- 只有該長輩目前的家屬或看護可以讀取與新增訊息。
- 訊息送出後不可由客戶端修改或刪除。
- 個人資料匯出會包含使用者自己在家庭群組送出的訊息。
- 帳號刪除會清除使用者在兩種聊天室送出的訊息與圖片。
- 長輩已無任何照護成員時，原有清除流程會遞迴刪除兩種聊天室。

## 舊資料相容

舊長輩資料可能沒有 `familyGroupId`。App 仍會直接以 `patientId` 推導固定群組，
因此不需要先批次搬移舊資料；新建立的長輩會保存 `familyGroupId` 供後續管理與稽核使用。
